## 1. Q1 设备供应与唯一上限

用户口径：*「设备无限供应，但是天有洪炉最多放置 12 台。」*

| 项 | 结论 |
|---|---|
| 设备供应 | **无限**。设备数量由产量需求与优化目标决定，不是约束 |
| 唯一数量约束 | **天有洪炉 ≤ 12 台**（新增硬约束，记为 **R-060**） |

落地：

- 材料/设备成本**不进入目标函数**（因供应无限）。这解决了此前 Q1 里「没有建造材料数据」的问题——**根本不需要**。
- `R-060` 要作为硬约束进验证器；若优化结果需要超过 12 台天有洪炉，应报「产能不足」而不是静默超限。
- 需确认：**12 台**是**每基地**还是**全局**？（R-002、R-003 都是「每基地」口径，推测同为每基地，待确认。）

## 2. Q2 输出形态

用户口径：*「算法计算出蓝图的 json，再交由前端或者其他方法可视化。」*

→ 采用**方案 A**：算法只负责算出 **JSON**，可视化是**下游消费者**。此前担心的「游戏可导入蓝图字符串」**不在范围内**。

因此算法与可视化之间需要一个稳定的**契约**。建议的 I/O：

### 2.1 输入：`PlanningRequest`

| 字段 | 类型 | 说明 |
|---|---|---|
| `targetProduct` | string | 目标产物名（规范名） |
| `targetRatePerMinute` | number | 目标产量 |
| `baseType` | enum | 主基地 80x80 / 副基地 50x50 |

| `fixedPaths` | map | 可选：用户显式指定的配方路径 |

### 2.2 输出：`Blueprint`

| 字段 | 说明 |
|---|---|
| `baseType` / `bounds` | 基地类型与边界（G-001 整数坐标） |
| `devices[]` | 每台设备：`deviceTypeId`、`position`（左下角整数坐标）、`rotation`（0/90/180/270）、`recipeId`、`tags` |

| `ruleReport` | 每条规则的校验结果 |
| `stats` | 设备数量、面积、额定功率、物料平衡表 |

坐标一律为**整数格**索引（G-001），可视化的像素缩放由前端负责。

## 3. Q5 优化目标由用户选择 —— 这改变了架构

用户口径：*「这个交由使用者决定，是最省电，还是最省设备，还是面积最小，或者单纯是空地太大想把空地占满，不由我来决定。」*

**这是本轮最重要的一条。** 它意味着 Q5（多路径选择）不能由算法写死，而必须变成**可插拔的目标函数**。

### 3.1 目标函数枚举

| 目标 | 含义 | 备注 |
|---|---|---|
| `MIN_POWER` | 最省电 | 用**额定功率**做比较量（见 §3.3）；**仅模块层可选** |
| `MIN_DEVICES` | 最省设备 | 设备总数最少 |
| `MIN_AREA` | 面积最小 | 占地最小；**基地层固定使用此项** |
| ~~`FILL_SPACE`~~ | ~~占满空地~~ | **已作废**——用户说明当时只是开玩笑，不会有用户做这种产线 |

### 3.2 目标的作用域分两层（第五轮已确认）

用户的补充口径：*「"规划阶段不考虑电力消耗"是指做整个基地的蓝图，对于单个模块还是要根据用户的选择来规划，整个基地的蓝图优先考虑的是面积，为了省电去牺牲面积反而得不偿失。」*

| 层级 | 优化目标 | 电力 |
|---|---|---|
| **模块层** | **由用户选择**（最省电 / 最省设备 / 最小面积） | 作为代价项 |
| **基地层** | **固定面积优先** | 不作为目标 |

因此 `objective` 字段只在模块层生效；基地层不因省电而扩大占地。详见 `agents/phase-01-12-goals-and-catalyst.md` §3。

### 3.3 「最省电」的口径需要澄清

你此前明确说过「规划阶段不考虑电力消耗」，现在又要把「最省电」作为可选目标。我的理解是**两者不矛盾**：

- **用于目标比较**：使用设备表里的**额定耗电（kW）**，作为路径优劣的**成本权重**；
- **不做的事**：仍然不做电力平衡校验、不做电池调度。

即：**耗电只作为代价函数的一项，不作为可行性约束。** 这条请确认。

## 4. ⚠ 新发现：催化剂/供气 6/min 与设备数量不是线性关系

算 Q5 的路径成本时，我发现 A-3 与 B-8 的两条「6/min」其实指向**同一个机制**，而且它是**每台设备各自扣一份**，**不随配方吞吐缩放**。这会显著改变物料平衡。

### 4.1 推导

以**液气转化机（气体产出）**为例，源表第 131–136 行的共同特征：

| 项 | 值 |
|---|---|
| 反应时间 | 2s |
| 产物 | 1（个/滴） |
| 催化剂列 | `液化息壤`，速率 `6` |
| 单机配方次数 | `60 / 2 = 30` 次/分钟 |
| **单机毛产出** | `1 × 30 = 30/min` |
| **单机催化剂消耗** | **`6/min`（固定，与配方次数无关）** |
| **单机净产出** | `30 - 0 = 30/min` 的产物，但**额外要喂 6/min 液化息壤** |

关键：`30 次/分钟` 的配方次数**不会**让催化剂变成 `180/min`。催化剂是**按分钟计的固定开销**。

### 4.2 连锁后果（举例）

- 1 台液气转化机需 `6/min` 液化息壤；
- 液化息壤由**反应池**供给：`1 息壤 + 1 清水 → 1 液化息壤`，2s → `30/min` 每台；
- 所以 **1 台反应池的液化息壤产出，会被约 5 台液气转化机吃光**（`30 / 6 = 5`）。

**这意味着催化剂不是免费的边角料，而是一条独立的上游支线，且其规模由"设备台数"而不是"产量"决定。** 若规划器按「1 台设备 = 30/min 产出」线性放大而忽略催化剂，会得出无法自洽的产线。

### 4.3 需要确认的三个点

1. **催化剂是"每台设备固定 6/min"，还是"每次配方固定 6 滴"？**
   你 A-3 的原话是「固定消耗每分钟 6 滴」，我据此按**每台 6/min** 建模；但源表列名是「催化剂速率（min）」，与"固定消耗"仍有张力。请最终定调。
2. **设备未达满产时，催化剂按比例降还是仍按 6/min？**
   若设备只跑一半时间，是消耗 `3/min` 还是 `6/min`？这影响部分负载场景。
3. **B-8 的气体散布机 6/min 是否同一机制？**
   它的范围是 6–30/min、效果恒定；催化剂是固定 6/min。数值相同、行为相似，我倾向于是**同一套"按分钟固定开销"机制**，请确认。

### 4.4 顺便验证了可行性

`气态赫铜` 那条链（气体反应炉第 130 行，`2 气态赫铜 + 1 息壤气 → 1 气态灼铜`，2s）看似吃亏，但催化剂由上游供给：

- 气态赫铜：提纯机（气体模式）第 125 行 = `30/min` 毛产出，**另有 6/min 分离芯的开销**；
- 息壤气：固气转化机（气体产出）第 145 行，但该机**自己也要 6/min 息壤气**做催化剂（自循环）；
- 一个基地只有 12 台天有洪炉（R-060），而**只有天有洪炉能产息壤**（第 119–121 行），所以息壤的产能上限是整条链的瓶颈。

**结论：息壤（以及依赖它的气态链）的产能上限由「12 台天有洪炉」这一条硬约束决定，规划器必须把它作为顶层容量校验。**
