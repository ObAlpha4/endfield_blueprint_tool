## 2. B-1 气体散布机的定位

用户原话口径：*「不要改动设备的分类，气体散布机属于特殊的设备，你把它理解成需要通入气体的供电桩就行了。规则中应该说的是指气体散布机产生环境。」*

- **分类保持源文件原样**：`气体散布机` 仍归 `合成制造`（设备表 row40）。此前提出的「新增第 7 类环境供应」**作废**。
- 建模定位：**环境版的供电桩**——同样是「一个小设备 + 一片覆盖范围」，区别只在于它自己需要气体输入、且覆盖范围内是环境而非电力。

| 维度 | 供电桩 | 气体散布机 |
|---|---|---|
| 占地 | 2x2 | 3x3 |
| 覆盖 | 12x12 | 13x13 |
| 覆盖判定 | 设备至少一格在内 | 设备须完全在内 |
| 覆盖可否相交 | 可以相交 | 不可相交，可相切 |
| 自身是否需要输入 | 不需要 | 需要气体，6–30/min |
| 是否耗电 | — | 0 kW（R-051 也不要求它接供电桩） |
| 输出 | 电力 | 环境（稳定/湿润/酸性/息壤） |

- 与固气转化机、液气转化机**无关**（B-8 明确），不要把它当作转化链的一环。

## 3. B-5 净水节点决策链

用户方案：

1. **不勾选净水节点** → 所有污水由废水处理机处理（销毁，A-2）。
2. **勾选净水节点** → 其中 360/min 的污水送往净水节点；净水节点返回 12/min 壤晶废液。
3. 对返回的 12/min 壤晶废液，再让用户选择**是否纳入产线规划**。

落地：这是**规划输入参数**，不是规则。建议 `PlanningOptions` 增加：

| 字段 | 类型 | 说明 |
|---|---|---|
| `useWaterPurifier` | bool | 是否启用净水节点 |
| `waterPurifierThroughput` | 360/min 常量 | R-053 给定 |
| `waterPurifierReturn` | 12/min 壤晶废液常量 | R-053 给定 |
| `reuseReturnedBrineWaste` | bool | 返回的壤晶废液是否纳入产线 |

注意：勾选后**仍可能有剩余污水**超过 360/min 的处理能力，超出部分仍需废水处理机或缓存，规划器应显式处理这个余量。

## 4. B-6 反应池缓存格模型

用户例子：

> `1 液化息壤 + 1 污水 → 1 壤晶废液 + 1 惰性壤晶废液`（第 116 行）
> 这个反应有 **4 种液体**，会占用 **4 个缓存格**。用反应池只能进行这个反应；用扩容反应池还可以加入 `0.5 蓝铁粉末`，产出 `0.5 壤晶` 和 `0.5 污水`。

由此确定的口径：

- **计数单位是「物料种类」占用的缓存格，不是配方数。**
  上例涉及液化息壤、污水、壤晶废液、惰性壤晶废液共 4 种，占 4 格。
- **反应池 5 格 / 扩容反应池 8 格是「同时涉及的物料种类上限」**，与 R-046 的「每格一种物料、每格最多 50 个」一致。
- 因此「可同时进行多个配方」的本质是：**多个配方的物料种类总和不超过缓存格数**。
  扩容 8 格 - 上例 4 格 = 剩 4 格，于是还能容纳 `蓝铁粉末 / 壤晶 / 污水` 这组（污水与上例共用一格），即用户描述的追加反应。
- 用户提到的 `0.5` 是**按配平比例折算的量**，说明扩容池里跑的是**按比例缩放的组合反应**，而不是整次配方。规划器需要支持「按目标产量比例缩放的物料流」。

待实现细节（不阻塞建模）：扩容池里多配方并行时，各配方的**节拍如何对齐**、`0.5` 这种非整数中间量如何在「每次配方产出整数」的规则下累计，需要由仿真阶段定义。

## 5. B-7 覆盖范围几何（供电桩）

用户口径：*「在坐标轴上画一个正方形，例如 (0,0) 到 (12,12)，这个范围内的设备都能被供电桩供电，但设备边缘与供电范围边缘相切则不会通电。所有通电和环境判定都是立刻生效。」*

**已由实机截图标定，细化规则见 `agents/phase-01-7-coverage-geometry.md`。** 要点：

- 覆盖方块是 **12×12 格**（供电桩）/ **13×13 格**（气体散布机），边界压在**网格线**上；
- 判定按**格心**：设备每一格的格心落在覆盖范围内才算被覆盖；
- **相切不算**：设备边缘与覆盖边缘重合 → 不通电；
- 供电桩「至少一格在内」；气体散布机「完全在内」；
- 判定立刻生效。

附图（供电桩）已逐项验证：3x3 的粉碎机**贴住覆盖左边缘 → 断电**，同列正下方完全在内的协议储存箱**有电**。两者相对位置相同、仅差一个「贴边」，正好钉死这条规则。

唯一剩余：覆盖方块相对设备原点的**偏移量**待实测（A：原点起；B：以设备居中），先按截图取居中并做成配置项。

## 6. B-8 气体散布机的输入

用户口径：*「它要求输入的气体至少是 6/min，最大是 30/min，在这个范围内输入多少都是固定产生环境。因此从节约的角度考虑，不如把气体散布机的消耗固定为 6/min。」*

- 输入区间：**6/min ≤ 输入 ≤ 30/min**。
- 在该区间内，环境生成的**效果恒定**，**不随输入量缩放**。
- 规划口径：**按 6/min 计**（下限最省）。低于 6/min 视为断供，环境消失（与 M0 已确认的「输入断供或小于 6/min 则环境不持续」一致）。
- 由此澄清：**A-3 的「催化剂 6/min」与这里的「6/min」不是同一个机制**，只是数值巧合。A-3 是配方固定消耗，这里是环境供气的下限。

## 7. B-9 物流设备占地

用户口径：*「这堆设备都是 1x1 占地，规则文档写了呀。」*

规则文档确实对这批物流设备给了尺寸（或可由「占据 1x1 的格子」直接读出）：

| 设备 | 占地 | 规则依据 |
|---|---|---|
| 传送带（含转弯） | 1x1 | 段 19、21「每单位的传送带占据 1x1 的格子」 |
| 分流器 | 1x1 | 段 22「分流器和汇流器会占据 1x1 的格子」 |
| 汇流器 | 1x1 | 同上 |
| 物流桥 | 1x1 | 段 24「会形成物流桥，占据 1x1 的格子」 |
| 物品准入口 | 1x1 | 段 27 与传送带族同列，按 1x1 处理 |
| 管道（含转弯） | 1x1 | 段 29、31 |
| 管道分流器 | 1x1 | 段 32 |
| 管道汇流器 | 1x1 | 段 32 |
| 管道桥 | 1x1 | 段 34 |
| 管道准入口 | 1x1 | 段 38 与管道族同列 |
| 供电桩 | **2x2** | 段 53「本身占据 2x2 的格子」——**唯一例外**，原清单里把它混进来是我的错 |

**仍需补的唯一一项**：这 11 种设备的**接口位置**。设备表不含它们，规则只给了尺寸与速度，没给「哪一面是入口/出口」。

**已由实机截图标定（详见 `agents/phase-01-8-logistics-and-storage-geometry.md`）**：

- 它们是**朝向可变器件**，没有固定的四面接口串；**形状由类型决定、朝向由 `rotation` 决定**，端口随旋转实例化；
- 端口数由类型决定：直段 2 口（相对面）、弯段 2 口（相邻面）、分流器/汇流器 3 口、桥 2 口（相对面）、准入口 2 口（相对面）；
- 因此这 11 种设备**不能套用「北/南/西/东固定串」的表结构**，需要「按类型 + 旋转生成端口」的规则；
- 图上确认物品网（黄色，直角）与管道网（蓝色，圆角）是**两个独立图层**。

符号辨认清单见该文档 §4，其中「分流器 vs 汇流器如何区分」尚未确认。

## 8. B-10 取货口/存货口与存取线（含附图）

用户口径：*「仓库取货口、仓库存货口的 3 宽普通面不就是 `nnn` 那面吗，接传送带就是对面的 `nsin` 或者 `nson`。源桩和基段没有方向性。」*

由此完全定死：

| 设备 | 3 宽普通面（贴靠面） | 物流面（接传送带） | 速度 |
|---|---|---|---|
| 仓库取货口 | 北面 `nnn` | 南面 `nson`（1 个固体出口） | 30/min（R-007） |
| 仓库存货口 | 南面 `nnn` | 北面 `nsin`（1 个固体入口） | 30/min（R-008） |

- 两个设备都是 3x1，**只有长边有 3 格**，所以「3 宽普通面」只能是 `nnn` 那一面；`n` 是单格，即两个短边。
- **源桩与基段无方向性**：贴合时不需要考虑朝向，只有位置（3 格边贴 3 格边）约束。

**附图解读（`docs` 外部的参考图）**：4x4 的仓库存取线源桩在上方，两个 3x1 的设备（左：仓库取货口；右：仓库存货口，橙色标记）紧贴在源桩**下方边缘**，各自占据 3 格宽度。这验证了 R-005 的「3 宽普通面必须贴靠源桩或基段」是**边贴边的紧邻**，且贴靠面就是 `nnn` 面。图中源桩四边各有一个螺栓状接头、中心一块绿色方格，可作为「无方向性连接点」的视觉参考。

要注意的是 R-004：基段必须连接源桩或已连接源桩的基段。

**已由实机截图标定（详见 `agents/phase-01-8-logistics-and-storage-geometry.md` §2）**：连接是**沿一条边相接、且该边上有正的共同长度**。已连接的基段顶边与源桩底边重合，但**左右不需要对齐**（允许部分搭接）；单独放置的基段会被标为「未连接」。判定：两设备占地矩形**边贴边且共同长度 > 0**，据此把 R-004 变成「所有基段须与至少一个源桩连通」的图论校验。

## 9. B-11 协议核心的取货口数量

用户口径：*「协议核心的每个取货口都是单独的 30/min。」*

- 协议核心西/东面原始串 `nsonnsonnson` 分词为 `n, so, n, n, so, n, n, so, n`，即**每面 3 个独立的固体出口**。
- 每个口**独立按 30/min** 计，不做合并。
- 同理北/南面 `nsisisisisisisin` = `n, si×6, n`，即**每面 6 个独立的固体入口**。

因此协议核心的聚合吞吐上限为：入口 `6 × 2 面 × 30 = 360/min`，出口 `3 × 2 面 × 30 = 180/min`。这直接决定 R-007/R-008 的容量校验。
