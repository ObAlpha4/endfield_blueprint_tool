| 编号 | 内容 | 当前临时口径 |

已由用户明确「第一版可以不做」的部分，不计为阻塞：

- **多电池调度**（R-069：只烧一种电池，按中容武陵电池 3200 kW 估算，3 台 = 9600 kW 基准）→ 不做精细电力平衡，只做「总耗电 ≤ 基准」的合理性提示。
- **材料清单 / 建造顺序**（Q1：设备无限供应，材料成本不进目标函数）→ 不在范围内。

## 2. 施工单（按依赖顺序）

### 步骤 1 — 统一数据入口（解析器）

**做什么**：把四份源文件解析成规范化中间数据（JSON），后续所有模块只读这份数据。

- 设备表：`{原始值, 规范值, 来源行号}` 三列分立；端口按「`n` 占 1 字符、其余标记占 2 字符」最长匹配分词；断言「分词格数 = 宽/高」。
- 配方表：保留空单元格的位置语义（单输入/单输出不得填成「无」或 `0`）；区分两类空产物行 —— 废水处理机 = 销毁（`outputs: []`）、气体散布机第 126–129 行 = 环境生成特例。
- 发电表：6 条，单位 kW / 秒。
- 规则文档：不做自动解析，人工维护为带编号的规则元数据。

**验收**：`tools/validate_sources.py` 的全部断言纳入解析器；解析结果对同一输入**可重复**（逐字节一致）。

**已有基础**：`tools/validate_sources.py`（`read_sheet` / `tokenize` 可直接复用）。

### 步骤 2 — 领域模型落地

**做什么**：按 `design/domain-model.md` §6 实现 `DeviceType` / `Port` / `Recipe` / `Item` / `DeviceInstance` / `Blueprint` 等对象。

- 坐标与旋转严格按 G-001：左下角整数坐标；顺时针 0/90/180/270；旋转只交换宽高。
- 端口局部格映射：北 `(w-ordinal, h-1)`、南 `(ordinal-1, 0)`、西 `(0, h-ordinal)`、东 `(w-1, ordinal-1)`；面内排列方向：北东→西、南西→东、西北→南、东南→北。
- 物流元件（11 种）**不套用四面接口串**，按「类型 + 旋转生成端口」建模；端口数：直段/弯段/准入口 = 2、**桥 = 4**、分流器/汇流器 = 3 或 4。

**验收**：单元测试覆盖 —— 旋转映射、端口格坐标、桥的四端口语义、`nfin` → `n, fi, n` 分词。

### 步骤 3 — 线性物料平衡求解（替换树展开）

**做什么**：这是**最关键**的一步。以「每条配方的投用台数」为变量、以「每种物料的产消平衡」为方程，求满足目标产量与非负约束的解。

必须处理的机制：

- **自持环**：`荞花 → 荞花种子 → 荞花`、`砂叶 → 砂叶种子 → 砂叶`、`赤铜溶液 → 气态赤铜 → 赤铜溶液`（当前树展开在这三处报出 −21 / −15 / −7 的假缺口）。
- **催化剂净额**（R-061）：固气/液气转化机每台固定 6/min，可能由本机产物自供（如第 145 行固气转化机自产息壤气又自耗 6/min），必须按净额入方程。
- **销毁边**（A-2）：`outputs: []` 只记消耗不记产出。
- **污水分配链**（R-068）：启用净水节点时先吃满 360/min，余量交废水处理机销毁。
- **反应池并行**（R-062 / R-046 / B-6）：共享输入池上并行执行所有匹配配方，约束是「涉及的总物料种类 ≤ 缓存格数」（反应池 5 / 扩容 8）。

**验收**：对「重息壤 12/min」求解后**所有物料净额为零或为正**；设备台数向上取整后重新验算仍在容差内；天有洪炉 ≤ 12 台（R-060）作为顶层校验。

### 步骤 4 — 规则验证器

**做什么**：R-001~R-069 逐条可独立运行，输入一份蓝图，输出每条规则的通过/失败与证据。

密度最高的几组：

| 组 | 校验内容 |
|---|---|
| 几何 | 重叠（整数格集合相交）、G-001 整数对齐、设备在基地范围内 |
| 覆盖 | 供电桩「至少一格格心在内」、气体散布机「全部格心在内」、相切不算、气体散布机范围两两不相交、覆盖方块偏移 |
| 仓储 | 源桩 ≤ 2、基段数量上限（主 5 / 副 12）、基段连通性（边贴边且共同长度 > 0 的邻接图）、取货口/存货口 `nnn` 面贴靠、协议核心恰好 1 个 |
| 物流 | 端口类型匹配、长度 ≤ 80、传送带 30/min、管道 120/min、反向/双弯角同格禁止、同格规则（管道族 vs 传送带族） |
| 容量 | 全局天有洪炉 ≤ 12、缓存格数与每格 50 上限、协议核心聚合吞吐（入 360/min、出 180/min） |

**验收**：`design/coverage-geometry.md` §5 与 `design/logistics-and-storage-geometry.md` §3 的验证器用例表全部实现并通过。

### 步骤 5 — 模块模板库 → 模块内布局

- 先做参数化模块模板（精炼、粉碎、配件、塑形、灌装、封装、反应池、提纯、液气/固气转化、发电、仓储）。
- 同配方设备成排/成阵列；输入面统一朝一侧、输出面朝另一侧；中间留物流通道。
- 供电桩放模块中心或边缘（覆盖优先）；有环境需求的设备**集中成组**，一个气体散布机覆盖一组。
- 模块层目标函数由用户选：`MIN_AREA` / `MIN_DEVICES` / `MIN_POWER`（电力只作代价项，不作约束）。

### 步骤 6 — 基地层拼接与物流布线

- 先放骨架：协议核心（软性偏好默认「距基地拐角纵横各 3 格」）、源桩、基段、取货口/存货口、外部资源接口、暗管接口。
- 基地层固定**面积优先**；必须输出并校验供电覆盖、气体环境覆盖、协议核心位置（R-063）。
- 物流分三张网（固体传送带 / 液体管道 / 气体管道），默认单物运输；能分开就分开。
- 外部资源（R-001）：源矿/蓝铁矿/赤铜矿从仓库取，清水/沉积酸用水泵，惰气/息壤气用气体收集泵；需预留外围接口或未连接暗管出口。

### 步骤 7 — 可视化与蓝图导出

- 输出分层 2D 图：设备层 / 传送带层 / 管道层 / 覆盖层 / 标记层（物品网与管道网必须是**两个独立图层**）。
- 输出设备清单、速率表、电力平衡表、物料平衡表、规则校验报告。
- 导出格式：**自定义 JSON**（Q2 方案 A 已定），字段约定在进入本步骤时定稿。

## 3. 技术债（已知，需带着走）

| 项 | 说明 | 处理建议 |
|---|---|---|
| 树展开不闭合 | `tools/plan_throughput.py` 的固有缺陷，已在 `plan_output.txt` 与重息壤示意图中显式标注为「结构示意，不是可施工蓝图」 | 步骤 3 用线性求解替换；**不要**在树展开上继续打补丁 |
| 设备台数为小数 | 核算输出 `1.87 台` 之类，落地必须向上取整 | 取整后重新验算物料平衡，把差额计入余量 |
| 提纯机（气体模式）需稳定环境 | 需气体散布机 + 惰气 6/min 支线 | 路径打分时必须计入这项成本 |
| `tools/show_facility.py` 依赖 pandas | 设备示意图绘制仍走 pandas 读表（其余脚本已改为直接解析 OOXML） | 若要合并进解析器，可复用 `tools/validate_sources.py` 的 `read_sheet`，去掉 pandas 依赖 |
| 设备表条目「灌装机（气体模式）」无配方引用 | 设备表有、配方表没有 | 已知，不进入实现假设 |
| 6 台资源开采设备不在 `DeviceType` 表内 | R-001 划到蓝图外 | 明确是否收录为「外部来源」类型 |

## 4. 完成度自查（做任何阶段前先过一遍）

1. 新引入的数值或规则，是否都能追溯到 `docs/` 源文件或用户确认？（不能则是「设计推测」，必须标注）
2. 是否把源表的空单元格填成了「无」或 `0`？（不允许）
3. 坐标是否都是整数、旋转是否只用了顺时针 0/90/180/270？（G-001）
4. 催化剂是否按「每台 6/min 净额」而不是「每次配方 6 滴」记账？（R-061）
5. 是否把电力当成了可行性约束？（基地层不校验功率，只做 9600 kW 合理性提示）
6. 是否为反应池记录了输出选择，并检查了「并行配方物料种类 ≤ 缓存格数」？
