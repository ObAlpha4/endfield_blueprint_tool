## 1A. 系统两段式结构（对话确认，架构约定）

系统拆成**只做一件事**的两部分，中间用一份可读的 `ChainPlan` 衔接：

```
用户输入：目标产物 + 目标产速 + 起始产物（可多选）+ 偏好
        │
        ▼
【第一部分】配方链路计算（链路求解器）
  输出 ChainPlan：物料产消平衡、每种物料的净额、每条配方的投用台数、
                  催化剂净额（含池化）、外部净进口、起始产物边界
        │
        ▼
【第二部分】模块化蓝图搭建（蓝图搭建器）
  输入 ChainPlan + 起始产物选择
  输出 Blueprint JSON：设备坐标与旋转、设备运作的配方、输出口产物标记、
                        传送带与管道、分流/汇流/桥/准入口、供电桩与气体散布机、仓储存取骨架
```

### 1A.1 为什么必须让用户选起始产物

**起始产物 = 本段产线从仓库取货口取什么**，也就是「蓝图负责到哪一层为止」。它直接决定产线能不能模块化批量复制：

- 以重息壤为例：若把起点定在**天有洪炉产息壤**，天有洪炉受 R-060 全局 ≤ 12 台限制，整条产线就不能批量复制；
- 若把**天有洪炉单独做成一个模块**，而重息壤产线的起点定为**取货口从仓库取息壤**，重息壤段就可以任意复制；
- 两端都由用户决定，系统只负责给出可行、可复刻的方案。

**边界规则**：

- 起始产物在 ChainPlan 里是**外部输入**（仓库取货口，速度上限 30/min/口，R-007）；
- 任何**不进蓝图**的外部资源（源矿/蓝铁矿/赤铜矿来自仓库，清水/沉积酸来自水泵，惰气/息壤气来自气体收集泵，R-001）**自动**是外部输入，不需要用户选；
- 目标产物之外的多余产物按副产物处理（存货口返回 / 销毁，R-008 / A-2）；
- 用户不选起始产物时，求解器默认回溯到 R-001 的外部资源清单。

### 1A.2 起始产物与全局约束的关系

某些约束是**全局**的（R-060 天有洪炉 ≤ 12 台），它约束的是「整个蓝图里设备总数」而不是某一段链路：

- 用户把**息壤**选为起始产物（从仓库取）→ 天有洪炉不出现在本蓝图，R-060 不参与本蓝图的校验（上游由另一个独立模块负责）；
- 用户**不**选息壤为起始产物、让本蓝图自己产息壤 → 蓝图里出现天有洪炉，R-060 作为蓝图层校验项参与；
- 因此 **R-060 是蓝图层的校验项，不是链路层的求解约束**，这一分工在第二部分落实（链路层只回答「要几台天有洪炉」）。

### 1A.3 与用户输入/输出的对应

| 项 | 归属 | 说明 |
|---|---|---|
| 目标产物 + 目标产量 | 输入（必填） | 整个系统的求解目标 |
| 起始产物 | 输入（选填、可多选） | 未填则回溯到 R-001 外部资源；填入后成为仓库取货口边界 |
| 偏好 | 输入（选填） | 模块层目标函数 `MIN_AREA` / `MIN_DEVICES` / `MIN_POWER`；电力只作代价项 |
| 设备坐标与旋转 | 输出（第二部分） | `DeviceInstance.position` / `rotation`，整数格（G-001） |
| 设备运作的配方 | 输出（第二部分） | 每个 `DeviceInstance` 实际执行的 `Recipe`（一般设备按输入自动选配方，R-062） |
| **输出口产物标记** | 输出（第二部分） | 每个输出端口的 `itemFilter`（取货口/准入口标记，R-007 / R-016 / R-024） |
| 物流与覆盖 | 输出（第二部分） | 传送带/管道/分流/汇流/桥/准入口、供电桩与气体散布机覆盖 |
| 校验报告与统计 | 输出（两部分） | 第一部分出物料平衡，第二部分出 R-001~R-069 逐条校验 |

## 2. 施工单（按依赖顺序）

### 步骤 1 — 统一数据入口（解析器）✅ 已完成

**做什么**：把四份源文件解析成规范化中间数据（JSON），后续所有模块只读这份数据。

- 设备表：`{原始值, 规范值, 来源行号}` 三列分立；端口按「`n` 占 1 字符、其余标记占 2 字符」最长匹配分词；断言「分词格数 = 宽/高」。
- 配方表：保留空单元格的位置语义（单输入/单输出不得填成「无」或 `0`）；区分两类空产物行 —— 废水处理机 = 销毁（`outputs: []`）、气体散布机第 126–129 行 = 环境生成特例。
- 发电表：6 条，单位 kW / 秒。
- 规则文档：不做自动解析，人工维护为带编号的规则元数据。

**验收**：`tools/validate_sources.py` 的全部断言纳入解析器；解析结果对同一输入**可重复**（逐字节一致）。

**落地位置**：`src/endfield/sources/{ooxml,parser,emit}.py` + `src/endfield/cli.py`；
产物 `data/derived/sources.json`；`tools/validate_sources.py` 保留为兼容入口（转调解析器）。
**实测**：46 行设备断言全绿；151 条配方；6 条发电；111 种物料；`cli repeat` 两次 SHA256 一致。

### 步骤 2 — 领域模型落地 ✅ 已完成

**做什么**：按 `design/domain-model.md` §6 实现 `DeviceType` / `Port` / `Recipe` / `Item` / `DeviceInstance` / `Blueprint` 等对象。

- 坐标与旋转严格按 G-001：左下角整数坐标；顺时针 0/90/180/270；旋转只交换宽高。
- 端口局部格映射：北 `(w-ordinal, h-1)`、南 `(ordinal-1, 0)`、西 `(0, h-ordinal)`、东 `(w-1, ordinal-1)`；面内排列方向：北东→西、南西→东、西北→南、东南→北。
- 物流元件（12 种 = 规则段 2 的 10 种器件 + 物品弯段 + 管道弯段）**不套用四面接口串**，按「类型 + 旋转生成端口」建模；端口数：直段/弯段/准入口 = 2、**桥 = 4**、分流器/汇流器 = 3 或 4（分流器 1 进 3 出、汇流器 3 进 1 出）。
- 物品品类按用户确认的关键词规则判定，并含**容器例外**（`X瓶（装有Y溶液）` 本身是固体物品）。
- `协议核心` 按**特殊设备**处理：保留权威规格与端口，但不进 `DeviceType` 列表，单列为基地骨架必需件（每个基地有且只有 1 个，R-006）。

**验收**：单元测试覆盖 —— 旋转映射、端口格坐标、桥的四端口语义、`nfin` → `n, fi, n` 分词。
**落地位置**：`src/endfield/domain/` + `src/endfield/items.py`；`tests/` 共 83 项全绿。

### 步骤 3 — 线性物料平衡求解（替换树展开）

**做什么**：这是**第一部分**，只做「算清楚」，不摆设备。以「每条配方的投用台数」为变量、以「每种物料的产消平衡」为方程，求满足目标产量与非负约束的解，产出 `ChainPlan`。

必须处理的机制：

- **自持环**：`荞花 → 荞花种子 → 荞花`、`砂叶 → 砂叶种子 → 砂叶`、`赤铜溶液 → 气态赤铜 → 赤铜溶液`（当前树展开在这三处报出 −21 / −15 / −7 的假缺口）。
- **起始产物边界**（§1A）：起始产物是外部输入边，不为其求解上游配方；未指定则回溯到 R-001 的外部资源。
- **催化剂净额**（R-061 + `design/baseline-rules.md` §1.10）：

  - **除息壤家族以外的产物一律从简**：只需按配方向固气转化机通入息壤气、向液气转化机通入液化息壤，**不关心这些流体的来源**，也不做特殊催化处理；
  - **未通入催化剂前反应不进行**，且**拒绝「从本机产物回流当催化」的设计**（要跑起来才产催化剂、要催化剂才跑得起来 → 永远到不了稳态，也不接受人工预充作为答案）。求解器只输出催化剂来自合法来源的方案；
  - **只有息壤、息壤气、液化息壤这三个产物需要特殊处理**，催化剂入口是转化机**北面中格**（固气 `ngi` / 液气 `nfi`，见 §1.10 的端口表）。能不能「从原料分流」只看一件事——**催化剂与原料是不是同一种物料**：

    | 模式 | 配方 | 催化剂 | 催化剂与原料同物？ | 合法来源 | 单台净额 |
    |---|---|---|---|---|---|
    | 固气 · 气体产出 | 息壤 → 息壤气 | 息壤气 | ❌（气 vs 固） | ② 别处（野外 150/min 或另一产息壤气的工序） | 息壤 −30 / 息壤气 **−6**（须外补） |
    | 固气 · 固体产出 | 息壤气 → 息壤 | 息壤气 | ✅ | ① 原料分流，或 ② 别处 | 息壤气 −36 / 息壤 +30 |
    | 液气 · 气体产出 | 液化息壤 → 息壤气 | 液化息壤 | ✅ | ① 原料分流（上游多备 `6N`），或 ② 别处 | 液化息壤 −36 / 息壤气 +30 |
    | 液气 · 液体产出 | 息壤气 → 液化息壤 | 液化息壤 | ❌（气 vs 液） | ② 别处 | 息壤气 −30 / 液化息壤 +24 |

  - N 台并联时催化需求是**常量 `6N`**，与各台在生产什么配方无关，因此「反应量 / 催化量」的流量分配恒为线性，**不需要 0-1 变量**区分「催化边 / 原料边」。
- **催化剂边必须如实建边、且要能报出缺口**（§1.10.3）：求解器把这三种产物当普通物料边处理，但必须把「某反应的产物 = 某反应的催化剂」这条依赖建成边，并在候选方案里**直接排除产物自循环的拓扑**；凑不出催化时报「必须由外部/其他模块提供 X 的催化量」。最紧的缺口是**息壤气**（唯一蓝图外来源是野外 150/min）与**液化息壤**（来路只有液气 · 液体产出与反应池 113）。
- **息壤气的多路分配**：野外息壤气（150/min）作为一条外部净进口边，剩余流量在「反应原料 / 产息壤 / 催化 / 净剩余」之间自由分配，不预设优先级；设备自产息壤气按净额混入同一物料边（§1.10）。
- **销毁边**（A-2）：`outputs: []` 只记消耗不记产出。
- **污水分配链**（R-068）：启用净水节点时先吃满 360/min，余量交废水处理机销毁。
- **反应池并行**（R-062 / R-046 / B-6）：共享输入池上并行执行所有匹配配方，约束是「涉及的总物料种类 ≤ 缓存格数」（反应池 5 / 扩容 8）。

**ChainPlan 必须输出**：每种物料净额、每条配方的投用台数、催化剂净额（含池化后的总量）、外部净进口清单、起始产物边界、物料流图的边（谁产谁耗）。

**验收**：对目标产物求解后**所有物料净额为零或为正**；设备台数向上取整后重新验算仍在容差内；起始产物边界之外的物料只作为外部输入出现，不再展开上游配方；**息壤家族三种产物的催化剂净额可追溯**——要么由原料分流供给，要么明确报出外部/其他模块必须提供的催化量；**方案里不出现「产物回流当催化」的拓扑**（§1.10）。

### 步骤 4 — 规则验证器

**做什么**：R-001~R-069 逐条可独立运行，输入一份蓝图，输出每条规则的通过/失败与证据。

密度最高的几组：

| 组 | 校验内容 |
|---|---|
| 几何 | 重叠（整数格集合相交）、G-001 整数对齐（顶点与格线均为整数）、设备在基地范围内 |
| 覆盖 | 供电桩 `D ∩ C ≠ ∅`、气体散布机 `D ⊆ C`、相切不算（格集合不相交）、气体散布机范围两两不相交、范围居中（四周外扩格数相等、边缘压在整数格线上） |

| 边界 | 设备与物流元件完全落在基地矩形内（主 80×80 / 副 50×50，C-3），边界闭合 |
| 容量 | 缓存格数与每格 50 上限、协议核心聚合吞吐（入 360/min、出 180/min）；天有洪炉 ≤ 12 台（R-060）只在**蓝图包含天有洪炉时**才参与本蓝图的校验（§1A.2） |

**验收**：`design/coverage-geometry.md` §5 与 `design/logistics-and-storage-geometry.md` §3 的验证器用例表全部实现并通过。

### 步骤 5 — 模块模板库 → 模块内布局（第二部分开始）

- 先做参数化模块模板（精炼、粉碎、配件、塑形、灌装、封装、反应池、提纯、液气/固气转化、发电、仓储）。
- **模块边界与起始产物对齐**（§1A）：起始产物是模块的「外部输入口」，对应取货口/暗管口；模块只负责起始产物之后的链路。若用户把天有洪炉单独作为一个模块，仓储模块就负责把息壤/液化息壤按 30/min/口的取货口送进下游模块。
- 同配方设备成排/成阵列；输入面统一朝一侧、输出面朝另一侧；中间留物流通道。
- 供电桩放模块中心或边缘（覆盖优先）；有环境需求的设备**集中成组**，一个气体散布机覆盖一组。
- **催化剂的供料支路要在模块内成型**（`design/baseline-rules.md` §1.10）：产催化剂的工序与消耗它的转化机放在同一模块内，出口接分流器 + 物品/管道准入口限速，分出 `6N`/min 走转化机**北面中格的催化口**；催化也可以由模块外的独立输入边供给。**不做「产物回流当催化」的支路**（无法启动）。
- 模块层目标函数由用户选：`MIN_AREA` / `MIN_DEVICES` / `MIN_POWER`（电力只作代价项，不作约束）。

### 步骤 6 — 基地层拼接与物流布线

- 先放骨架：协议核心（软性偏好默认「距基地拐角纵横各 3 格」）、源桩、基段、取货口/存货口、外部资源接口、暗管接口。
- 基地层固定**面积优先**；必须输出并校验供电覆盖、气体环境覆盖、协议核心位置（R-063）。
- 物流分三张网（固体传送带 / 液体管道 / 气体管道），默认单物运输；能分开就分开；长度按连续段校验（C-4）。
- 外部资源（R-001）：源矿/蓝铁矿/赤铜矿从仓库取，清水/沉积酸用水泵，惰气/息壤气用气体收集泵；需预留外围接口或未连接暗管出口。
- **息壤气这类紧缺气体允许在基地内做三路分配**（催化 / 反应原料 / 产息壤），由 `design/baseline-rules.md` §1.10 的物料边统一处理，不额外加优先级假设。

### 步骤 7 — 可视化与蓝图导出

- 输出分层 2D 图：设备层 / 传送带层 / 管道层 / 覆盖层 / 标记层（物品网与管道网必须是**两个独立图层**）。
- 输出设备清单、速率表、电力平衡表、物料平衡表、规则校验报告。
- 导出格式：**自定义 JSON**（Q2 方案 A 已定），字段约定在进入本步骤时定稿。
- 蓝图 JSON 必须包含用户要求的三项核心内容：**设备位置**（含旋转）、**每个设备实际运作的配方**、**输出口的产物标记**（`itemFilter`）；这三项由第二部分保证，第一部分只提供链路与速率依据。

## 4. 完成度自查（做任何阶段前先过一遍）

1. 新引入的数值或规则，是否都能追溯到 `docs/` 源文件或用户确认？（不能则是「设计推测」，必须标注）
2. 是否把源表的空单元格填成了「无」或 `0`？（不允许）
3. 坐标是否都是整数、旋转是否只用了顺时针 0/90/180/270？（G-001：设备边缘在整数格线上、顶点在整数坐标上）
4. 覆盖范围是否由设备位置与居中偏移直接推出（`(s−d)/2`），且判定只用整数格集合（`D ∩ C` / `D ⊆ C`）？
5. 催化剂是否按「每台 6/min 净额」而不是「每次配方 6 滴」记账？（R-061；N 台并联时催化总量是常量 `6N`，不需要 0-1 变量）
6. 催化剂来源是否只有「原料分流」与「产线其他地方/蓝图外输入」两种？是否出现了**产物回流当催化**的自循环设计？（不允许，见 `design/baseline-rules.md` §1.10）
7. 是否把电力当成了可行性约束？（基地层不校验功率，只做 9600 kW 合理性提示）
8. 是否为反应池记录了输出选择，并检查了「并行配方物料种类 ≤ 缓存格数」？
9. 是否把息壤产线（天有洪炉 → 息壤及其上下游）带进了阶段 1 的规划范围？（不允许；只有用户显式把息壤/天有洪炉选为起始产物时才进入后续阶段）
10. 链路计算是否止步于**用户选择的起始产物**（把上游留给仓库取货口，或留给另一个独立模块）？是否默认回溯到 R-001 外部资源？
11. 蓝图 JSON 是否包含**设备位置、每台设备运作的配方、输出口产物标记**这三项？
12. 全局约束（如 R-060 天有洪炉 ≤ 12）是否只在对应设备真的出现在本蓝图时才参与校验？
