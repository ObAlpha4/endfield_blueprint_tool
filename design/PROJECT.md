## 1. 项目目标

输入「目标产物 + 目标产量 + 基地类型 + 起始产物（选填）+ 偏好」，输出一份**可直接复刻的蓝图 JSON**（可视化由下游前端负责，不在本项目范围内）。

交付物形态已由用户确认（第三轮 Q2，方案 A），并按后续复盘细化为**两段式系统**：

```
用户输入：目标产物 + 目标产量 + 起始产物（选填、可多选）+ 偏好
        │
        ▼
【第一部分】配方链路计算 → ChainPlan（物料平衡、配方投用台数、催化剂净额、外部净进口）
        │
        ▼
【第二部分】模块化蓝图搭建 → Blueprint JSON（设备位置、设备运作的配方、输出口产物标记、物流、覆盖）
        │
        ▼
前端 / 其他方式可视化
```

- **为什么要拆**：链路计算是纯数学（只要物料平衡），蓝图搭建是纯几何与布局；两者的失败原因、迭代节奏、可复用性都不同。拆开后第一部分可以独立验证物料平衡，第二部分可以独立验证几何规则。
- **起始产物由用户选择**：它决定「蓝图负责到哪一层为止」，也就是本段产线从仓库取什么。以重息壤为例，起点若定在「天有洪炉产息壤」，天有洪炉受 R-060（全局 ≤ 12 台）限制，整条产线无法批量复制；把天有洪炉拆成独立模块、起点定为「仓库取息壤」，重息壤段就可以任意复制。**这个取舍完全交给用户，系统只负责给出可行、可复刻的方案**（必要时给方案对比）。
- 不选起始产物时，求解器默认回溯到 R-001 的外部资源清单（源矿/蓝铁矿/赤铜矿从仓库取，清水/沉积酸用水泵，惰气/息壤气用气体收集泵）。详见 `design/next-steps.md` §1A。

蓝图 JSON 需要包含：**设备位置与旋转、每台设备实际运作的配方、每个输出口的产物标记**（用户明确要求的三项）、传送带与管道、分流/汇流/桥/准入口、供电桩与气体散布机覆盖、仓储存取骨架与协议核心、规则校验报告、统计信息。

### 3.2 已固化的规则（完整清单见 `design/baseline-rules.md`）

- **单位与速率**：时间用秒；固体用「个」、液体/气体用「滴」；单机配方次数 = `60 / 反应时间`（对所有设备普遍成立，多台线性叠加）；传送带 30/min、管道 120/min、物流最大长度 80；功率单位 kW。
- **坐标与旋转**（G-001）：所有设备的**边缘严格位于整数坐标的格线上、顶点严格位于整数坐标上**；坐标原点为自身左下角；只能顺时针旋转 0/90/180/270，禁止镜像；旋转锚点为左下角；端口占用完整格子。
- **几何标定**（R-050/R-052/R-063）：供电桩 2x2、覆盖 12x12、设备至少一格在内、范围可相交；气体散布机 3x3、覆盖 13x13、设备须完全在内、范围不可相交但可相切；**覆盖范围同样是整数格正方形，且设备占地严格位于范围正中**（四周各外扩 5 格）；判定按**整数格集合**（供电桩 `D ∩ C ≠ ∅`、气体散布机 `D ⊆ C`）、**相切即格集合不相交**、立刻生效。详见 `design/coverage-geometry.md`。
- **仓储与存取线**（R-002~R-008、B-10）：源桩 ≤ 2 个/基地；基段主基地 ≤ 5、副基地 ≤ 12；「连接」= 边贴边且共同长度 > 0；取货口/存货口的 `nnn` 面贴靠源桩或基段，对面 `nson`/`nsin` 接传送带；协议核心每基地必须且只能 1 个，每个取货口独立 30/min。
- **物料模型**：`outputs: []` 表示销毁输入（废水处理机）；催化剂按**每台设备固定 6/min** 记账（R-061），与配方、产率无关，可能由本机产物自供，需按**净额**计算；缓存格数 = 输入物料种类数，每格上限 50（R-067）。
- **顶层容量约束**：全局天有洪炉 ≤ 12 台（R-060，所有基地相加，属于后续阶段的专项约束，不进阶段 1）；电力基准 3 台热能池 × 3200 kW = 9600 kW，1 主基地 + 3 副基地共用电量（R-069）。
- **优化目标分层**：模块层由用户选择（最省电 / 最省设备 / 最小面积），基地层固定**面积优先**；电力只作为模块层的代价项，不作为可行性约束。

### 3.4 已验证的结论与暴露的缺陷（重要）

**阶段 1 不做任何产线规划**，因此下面这些核算结果只用于**验证算法骨架与规则口径**，不是阶段 1 的交付内容，也不代表阶段 1 要考虑某条具体产线（尤其是息壤产线）。

- 结构正确的链路示例：`息壤气 ─提纯机(124)→ 重息壤气 ─固气转化机(149)→ 重息壤`，**完全绕开天有洪炉产重息壤**（天有洪炉仅用于产息壤本身）；总额定功率约 375 kW，远低于 9600 kW 基准。此处只作规则口径的示例，不作为阶段 1 的产线规划。
- **暴露的缺陷**：树形展开无法闭合自持环，物料平衡审计出三处缺口 —— 荞花 −21.00/min、气态赤铜 −15.00/min、砂叶 −7.00/min（其余 18 种物料恰好平衡）。
- **结论**：必须把「树展开」换成**线性物料平衡求解**（以每条配方投用台数为变量、以物料产消平衡为方程），这也是下一阶段最关键的算法改动。

## 4. 接下来的规划

按依赖顺序排列，详细版本见 `design/next-steps.md`。

1. **统一数据入口**：把源 xlsx/docx 解析成规范化中间数据（JSON），设备表「原始值 / 规范值 / 来源行号」三列分立；把 `validate_sources.py` 的断言纳入其中。
2. **落地领域模型**：按 `design/domain-model.md` 的 `DeviceType` / `Port` / `Recipe` / `DeviceInstance` 等对象实现，坐标与旋转按 G-001 与 `design/global-constraints.md`。
3. **线性物料平衡求解器（第一部分）**：替换树展开，闭合自持环；输入含**用户选择的起始产物**，输出 `ChainPlan`（每种物料净额、配方投用台数、催化剂净额、外部净进口、起始产物边界）。
4. **规则验证器**：R-001~R-069 逐条可独立运行，含密度最高的几何校验（覆盖、贴靠、连通性、重叠），并按 C-4（长度只算连续段）与 C-3（边界 = 基地矩形）落地。
5. **模块模板库 → 模块内布局 → 基地层拼接与布线（第二部分）→ 可视化导出**：模块边界与起始产物对齐，模块内成型催化剂的同源限速分流；蓝图 JSON 必须包含设备位置、设备运作的配方、输出口产物标记。
6. **贯穿性工作**：为每台反应池记录输出选择（`recipeId` 语义为「预期值」，设备按输入自动选配方）。

**未决参数：已清零**（2026 复核后定稿）：

| 项 | 结论 |
|---|---|
| C-4 | 物流长度**只算连续段**，断开元件（准入口 / 分流器 / 汇流器 / 物流桥 / 管道桥）自身不计入，逐段断言 ≤ 80 |
| C-3 | 最大可建造边界 **= 基地矩形**（主基地 80×80、副基地 50×50） |
| B-7 余项 | 覆盖范围是整数格正方形，设备占地严格居中（四周各外扩 `(s−d)/2` 格，两者都是 5 格），由设备位置直接推出 |

其余 C 类（导出 JSON 的字段约定、材料清单、分步建造顺序）已在第三轮确定「算法只产出 JSON，可视化交给前端」，可按需在阶段 7 补齐。

## 6. 怎么跑

环境：Python 3.12（`.venv`，已装 pandas / openpyxl / IPython 等）。

```powershell
# 校验源数据（接口串格数 = 宽/高；配方表结构；发电表数值）
.venv\Scripts\python.exe tools\validate_sources.py

# 产能核算：目标产物 + 目标产量 [/min] [min_devices|min_power]
.venv\Scripts\python.exe tools\plan_throughput.py 重息壤 12
.venv\Scripts\python.exe tools\plan_throughput.py 水蒸气 100 min_power
# 结果写入 tools\out\plan_output.txt

# 画单个设备的接口示意图
.venv\Scripts\python.exe tools\show_facility.py
```

> 三个脚本都可以直接从**仓库根目录**运行，路径均按脚本自身位置解析；生成物统一写入 `tools\out\`。
> 两段式系统的第一部分（配方链路计算）尚未落地，`tools/plan_throughput.py` 是要被它替换的树展开原型。
