### 3.2 已固化的规则（完整清单见 `design/baseline-rules.md`）

- **单位与速率**：时间用秒；固体用「个」、液体/气体用「滴」；单机配方次数 = `60 / 反应时间`（对所有设备普遍成立，多台线性叠加）；传送带 30/min、管道 120/min、物流最大长度 80；功率单位 kW。
- **坐标与旋转**（G-001）：所有设备顶点与整数坐标对齐；坐标原点为自身左下角；只能顺时针旋转 0/90/180/270，禁止镜像；旋转锚点为左下角；端口占用完整格子。
- **几何标定**（R-050/R-052/R-063）：供电桩 2x2、覆盖 12x12、设备至少一格在内、范围可相交；气体散布机 3x3、覆盖 13x13、设备须完全在内、范围不可相交但可相切；判定按**格心**、**相切不算**、立刻生效。
- **仓储与存取线**（R-002~R-008、B-10）：源桩 ≤ 2 个/基地；基段主基地 ≤ 5、副基地 ≤ 12；「连接」= 边贴边且共同长度 > 0；取货口/存货口的 `nnn` 面贴靠源桩或基段，对面 `nson`/`nsin` 接传送带；协议核心每基地必须且只能 1 个，每个取货口独立 30/min。
- **物料模型**：`outputs: []` 表示销毁输入（废水处理机）；催化剂按**每台设备固定 6/min** 记账（R-061），与配方、产率无关，可能由本机产物自供，需按**净额**计算；缓存格数 = 输入物料种类数，每格上限 50（R-067）。
- **顶层容量约束**：全局天有洪炉 ≤ 12 台（R-060，所有基地相加）→ 息壤产能上限 360/min；电力基准 3 台热能池 × 3200 kW = 9600 kW，1 主基地 + 3 副基地共用电量（R-069）。
- **优化目标分层**：模块层由用户选择（最省电 / 最省设备 / 最小面积），基地层固定**面积优先**；电力只作为模块层的代价项，不作为可行性约束。

### 3.4 已验证的结论与暴露的缺陷（重要）

以「重息壤 12/min」为目标的核算结果：

- 结构正确的链路：`息壤气 ─提纯机(124)→ 重息壤气 ─固气转化机(149)→ 重息壤`，**完全绕开天有洪炉产重息壤**（天有洪炉仅用于产息壤本身）；天有洪炉占用约 0.7 台，远低于 12 台上限；总额定功率约 375 kW，远低于 9600 kW 基准。
- **暴露的缺陷**：树形展开无法闭合自持环，物料平衡审计出三处缺口 —— 荞花 −21.00/min、气态赤铜 −15.00/min、砂叶 −7.00/min（其余 18 种物料恰好平衡）。
- **结论**：必须把「树展开」换成**线性物料平衡求解**（以每条配方投用台数为变量、以物料产消平衡为方程），这也是下一阶段最关键的算法改动。

## 4. 接下来的规划

按依赖顺序排列，详细版本见 `design/next-steps.md`。

1. **统一数据入口**：把源 xlsx/docx 解析成规范化中间数据（JSON），设备表「原始值 / 规范值 / 来源行号」三列分立；把 `validate_sources.py` 的断言纳入其中。
2. **落地领域模型**：按 `design/domain-model.md` 的 `DeviceType` / `Port` / `Recipe` / `DeviceInstance` 等对象实现，坐标与旋转按 G-001 与 `design/global-constraints.md`。
3. **线性物料平衡求解器**：替换树展开，闭合自持环；输出每种物料净额、设备台数（向上取整后验算）、外部净进口。
4. **规则验证器**：R-001~R-069 逐条可独立运行，含密度最高的几何校验（覆盖、贴靠、连通性、重叠）。
5. **模块模板库 → 模块内布局 → 基地层拼接与布线 → 可视化导出**。
6. **贯穿性工作**：为每台反应池记录输出选择（`recipeId` 语义为「预期值」，设备按输入自动选配方）。

**仅剩的 3 项未决参数**（都不阻塞建模，实现时做成配置项）：

| 项 | 内容 |
|---|---|
| B-7 余项 | 覆盖方块相对设备原点的**偏移量**（原点起 / 居中），已按「居中」预估，待实测 |
| C-4 | 物流「最大长度 80」中，**断开元件本身是否计入长度** |
| C-3 | 蓝图编辑器可建造边界是否等于基地矩形（基地 80x80 / 50x50 已确认） |

其余 C 类（导出 JSON 的字段约定、材料清单、分步建造顺序）已在第三轮确定「算法只产出 JSON，可视化交给前端」，可按需在阶段 7 补齐。

## 6. 怎么跑

环境：Python 3.12（`.venv`，已装 pandas / openpyxl / IPython 等）。

```powershell
# 校验源数据（接口串格数 = 宽/高；配方表结构；发电表数值）
.venv\Scripts\python.exe tools\validate_sources.py

# 产能核算：目标产物 + 目标产量 [/min] [min_devices|min_power]
.venv\Scripts\python.exe tools\plan_throughput.py 重息壤 12
.venv\Scripts\python.exe tools\plan_throughput.py 水蒸气 100 min_power
# 结果写入 tools\out\plan_output.txt

# 画重息壤链结构示意图
.venv\Scripts\python.exe tools\draw_heavy_loam_schematic.py

# 画单个设备的接口示意图
.venv\Scripts\python.exe tools\show_facility.py
```

> 四个脚本都可以直接从**仓库根目录**运行，路径均按脚本自身位置解析；生成物统一写入 `tools\out\`。
